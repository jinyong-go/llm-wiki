## 1. Bridge 드라이버
가장 보편적으로 사용되는 드라이버로, 동일 호스트 내 컨테이너 간의 통신을 담당한다.

### 1.1. 작동 원리
- **가상 브리지**: 호스트 커널에 `docker0`와 같은 가상 소프트웨어 스위치를 생성한다.
- **veth pair**: 컨테이너 생성 시 한 쌍의 가상 이더넷 인터페이스가 만들어져, 하나는 컨테이너 내부(`eth0`), 다른 하나는 호스트 브리지에 연결된다.
- **NAT(Network Address Translation)**: 컨테이너가 외부 네트워크와 통신할 때 호스트의 IP로 변환하여 전송하며, `iptables` 규칙을 통해 포트 매핑을 관리한다.
- **DNS 해석**: **사용자 정의 브리지**에서는 도커 내장 DNS 서버가 작동하여 컨테이너 이름이나 별칭으로 서로를 찾을 수 있다. (기본 브리지는 미지원)

### 1.2. 기본 Bridge vs 사용자 정의 Bridge
Docker는 보안과 유연성을 위해 **사용자 정의(User-defined) 브릿지** 사용을 강력히 권장한다.

| 구분 | 기본 Bridge (`bridge`) | 사용자 정의 Bridge |
| :--- | :--- | :--- |
| **자동 DNS 해소** | 지원 안 함 (IP로만 통신 가능) | **지원 함** (컨테이너 이름으로 통신 가능) |
| **서비스 격리** | 낮음 (모든 미지정 컨테이너가 공유) | **높음** (해당 네트워크 내 컨테이너만 통신) |
| **연결성 변경** | 컨테이너 재시작 필요 | **실시간** 연결/해제 가능 (`connect`/`disconnect`) |
| **유연성** | 설정 변경 시 Docker 데몬 재시작 필요 | 생성 시 서브넷, 게이트웨이 등 자유롭게 설정 |
| **Link 방식** | `--link` (Legacy, 정적 방식) 사용 필요 | 자동 및 동적 감지 (Service Discovery) |

## 2. Host 드라이버
컨테이너가 호스트의 네트워크 환경을 그대로 사용하는 방식이다.

### 2.1. 작동 원리
- 네트워크 격리(Namespace)를 수행하지 않는다. 컨테이너 내부의 프로세스는 호스트의 IP와 포트를 직접 점유한다.
- **성능**: 브리지나 NAT를 거치지 않으므로 네트워크 오버헤드가 거의 없는 네이티브 성능을 제공한다.
- **주의사항**: 포트 충돌 위험이 있으며, 보안상 격리 수준이 낮다. 리눅스 환경에서만 지원된다.

---

## 3. Overlay 드라이버
서로 다른 호스트(서버)에 있는 컨테이너들을 하나의 가상 네트워크로 연결한다.

### 3.1. 작동 원리
- **VXLAN(Virtual Extensible LAN)**: Layer 2 이더넷 프레임을 Layer 3 UDP 패킷으로 캡슐화하여 호스트 간 터널링을 수행한다.
- **제어 평면(Control Plane)**: Docker Swarm이나 외부 K/V 저장소를 통해 분산된 노드 간의 IP 정보를 동기화한다.
- **데이터 암호화**: 옵션을 통해 노드 간 통신 데이터를 AES로 암호화할 수 있다.

---

## 4. Macvlan 드라이버
컨테이너를 물리 네트워크의 실제 장비처럼 인식하게 만든다.

### 4.1. 작동 원리
- 호스트의 물리 인터페이스(예: `eth0`)를 부모로 하여 가상 하위 인터페이스를 생성한다.
- 각 컨테이너는 **고유한 MAC 주소**와 물리 네트워크 대역의 IP를 부여받는다.
- **용도**: 네트워크 홉을 최소화해야 하거나, 물리 네트워크 장비와 직접 통신해야 하는 특수 애플리케이션에 적합하다.
- **주의**: 호스트 커널 보안 정책상, 기본적으로 호스트와 해당 컨테이너는 직접 통신할 수 없다. (별도의 Macvlan 인터페이스 추가 필요)

---

## 5. IPvlan 드라이버
Macvlan과 유사하지만 MAC 주소를 관리하는 방식과 라우팅 메커니즘에서 차이가 있다.

### 5.1. 작동 원리
- **L2 모드**: 모든 컨테이너가 호스트의 **동일한 MAC 주소**를 공유하되 IP만 다르게 가져간다. 상위 스위치의 MAC 테이블 용량 제한(MAC Address Exhaustion)이 있는 환경에서 Macvlan의 대안으로 사용된다.
- **L3 모드**: 호스트가 컨테이너들의 라우터 역할을 수행한다. Layer 2 브로드캐스트가 발생하지 않아 대규모 네트워크 확장 시 성능 저하를 방지할 수 있다.

---

## 6. 드라이버별 비교표

| 드라이버 | 네트워크 범위 | 성능 | 격리 수준 | 특징 |
| :--- | :--- | :--- | :--- | :--- |
| **Bridge** | Single Host | 보통 | 높음 | 기본 설정, 자동 DNS(사용자 정의) |
| **Host** | Single Host | **최상** | 낮음 | 포트 매핑 불필요, Linux 전용 |
| **Overlay** | Multi Host | 낮음 (캡슐화) | 높음 | 클러스터 환경 필수 |
| **Macvlan** | Physical LAN | 높음 | 보통 (L2) | 고유 MAC 부여, 레거시 지원 |
| **IPvlan** | Physical LAN | 높음 | 보통 (L3) | MAC 공유 가능, 대규모 확장 |
