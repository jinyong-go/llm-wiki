2026-06-15 서버 수정 후 CPU 사용량 상승
수정된 부분은 다음과 같음:
1. netty 버전 업그레이드(4.1.42 -> 4.1.127)
2. 소켓 통신 패킷 길이 증가
3. pfx 파일 내 인증서 및 개인키가 여러개 존재함에 따라 alias로 사용할 인증서, 개인키를 keystore에서 찾은 후 사용

top과 jstack 명령어로 CPU 사용량 및 스레드 확인
-> nioEventGroupLoop이 평소보다 CPU 많이 사용하는 것 확인

최초 의심 지점은 netty 버전 변경
-> netty 버전 다운그레이드 후에도 CPU 사용량 높음

소켓 통신 패킷 길이 증가
-> 이전 규격으로 패킷길이를 짧게 호출해도 CPU 사용량 높음

이전 서버로 롤백
-> CPU 사용량 정상화

코드 변경사항 전체 확인
1. socket 처리 부분은 전문의 패킷 길이 변경 외에 없음
2. DB에선 지연이 발생(슬로우쿼리)하지 않았기 때문에 쿼리 변경은 문제 없다고 판단
3. 비즈니스 로직 처리 부분 확인하여 인증서 검증 시 발급자의 인증서를 가져오는 부분 변경 확인
   -> 기존에는 KeyStore 로드 후 메모리 상에 인증서와 개인키를 올려두고(필드) 사용했지만 지금은 2개의 인증서/개인키가 존재함에 따라 키스토어 접근하여 인증서 가져오도록 변경 확인

성능테스트로 확인
1. 기존 메모리에 필드로 올려둔 인증서로 검증하는 API 수백회 호출
2. 변경된 키스토어에서 인증서를 가져오는 서버 모듈로 API 수백회 호출

메모리 사용량 1<2 확인

Map 형식으로 alias를 키로 인증서와 개인키를 올려두고 키스토어가 아닌 맵에서 가져오도록 변경

개발 및 운영에서 반영 후 CPU 사용량 정상적으로 줄어드는 것 확인
