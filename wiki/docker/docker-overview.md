## 1. 개요
도커는 **컨테이너화(Containerization)** 기술을 사용하여 애플리케이션의 배포, 확장 및 관리를 자동화하는 오픈소스 플랫폼이다. 2013년 등장 이후 애플리케이션 개발 및 운영 방식에 혁신을 가져왔다.

## 2. 왜 컨테이너/가상화인가?
물리 서버 위에 직접 서비스를 구동하는 전통적인 방식 대신 추상화 계층을 사용하는 이유는 다음과 같다.

1.  **유연성 및 확장성**: 구성 변경이 용이하고 호스트 간 이동이 자유롭다. 필요에 따라 인스턴스를 즉시 늘리거나 줄일 수 있다.
2.  **자원 활용 효율성**: 하드웨어 자원을 동적으로 할당하여 유휴 자원을 최소화한다.
3.  **프로세스 격리**: 각 서비스의 코드, 설정, 의존성을 분리하여 상호 간섭을 방지한다. 특정 서비스의 업데이트가 다른 서비스에 영향을 주지 않는다.
4.  **환경 일관성**: "내 로컬에선 되는데?" 문제를 해결한다. 개발, 테스트, 운영 환경을 완전히 동일하게 유지할 수 있다.

## 3. 도커 vs 가상 머신(VM)
가장 큰 차이는 **OS 커널의 공유 여부**와 **가상화 수준**에 있다.

| 구분 | 도커 컨테이너 (Docker) | 가상 머신 (VM) |
| :--- | :--- | :--- |
| **핵심 기술** | 컨테이너 엔진 (Docker Engine) | 하이퍼바이저 (Hypervisor) |
| **OS 구조** | **호스트 OS 커널 공유** | **게스트 OS 포함 (Full OS)** |
| **격리 수준** | 프로세스 레벨 격리 (Namespace, Cgroups) | 하드웨어 레벨 가상화 (HW 기반 격리) |
| **크기** | 수 MB ~ 수백 MB (매우 가벼움) | 수 GB ~ 수십 GB (무거움) |
| **부팅 속도** | 초 단위 (프로세스 실행 수준) | 분 단위 (OS 부팅 필요) |
| **이식성** | 매우 높음 (엔진만 있으면 동일 작동) | 높음 (이미지 이동 가능하나 무거움) |

### 3.1. 상세 비교 분석
- **도커의 메커니즘**: 호스트 OS의 커널 기능을 직접 사용하여 프로세스를 격리한다. 가상 하드웨어가 없으므로 오버헤드가 거의 없고 성능이 네이티브에 가깝다.
- **VM의 메커니즘**: 하이퍼바이저가 하드웨어를 가상화하고 그 위에 전체 OS를 띄운다. 격리 수준이 더 높고 보안성이 우수하며, 서로 다른 커널 버전이나 OS를 실행해야 할 때 필수적이다.

## 4. 핵심 개념
- **[[docker-image]]**: 애플리케이션 실행에 필요한 모든 요소를 포함한 읽기 전용 템플릿. 계층형 파일 시스템을 사용한다.
- **[[docker-container]]**: 이미지를 실행한 상태의 인스턴스. 격리된 독립 환경을 제공하며 쓰기 가능한 레이어가 추가된다.
- **[[dockerfile]]**: 이미지를 생성하기 위한 명령어들이 포함된 자동화 스크립트.
- **Docker Registry**: 이미지를 저장하고 배포하는 시스템 (예: Docker Hub, ECR).

## 5. 주요 기술적 특징
1.  **네임스페이스(Namespaces)**: 커널 리소스(PID, Network, Mount 등)를 논리적으로 분리하여 독립된 환경 제공.
2.  **컨트롤 그룹(Cgroups)**: 컨테이너별 자원(CPU, 메모리, I/O) 사용량 제한 및 제어.
3.  **유니온 파일 시스템(UnionFS)**: 여러 레이어를 하나의 파일 시스템으로 통합 관리하여 공간 효율 극대화.
